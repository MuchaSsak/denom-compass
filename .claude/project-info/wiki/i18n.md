# i18n (English + Polish)

English is the source and default. Every page lives under `src/pages/[lang]/` (`getStaticPaths = langPaths`), URLs `/en/...` and `/pl/...`. Terminology rules: [[i18n-glossary]].

## UI strings - Lingui v6
- `t('English text')` everywhere (`.astro`, `.svelte`, `.ts`); the English string is the message id. `useT(lang)` (`src/i18n/index.ts`) returns the translator; Svelte islands get `lang` as a prop.
- Catalogs `src/locales/{en,pl}.po`, compiled on import by `@lingui/vite-plugin`.
- `npm run i18n:extract` uses the custom extractor `src/i18n/extractor.ts` (regex for literal `t('…')` calls). Dynamic ids are not extracted, so labels built from data use literal maps (`src/i18n/labels.ts › familyName`).
- After adding UI text: extract, fill every empty `msgstr` in `pl.po`, rebuild. The extract table must show 0 missing for `pl`.
- Helpers: `href(lang, path)`, `stripLang`, `LANG_NAMES`, `OG_LOCALE`, `isLang`.

## Data - Polish overlays
- `src/data/pl/*.ts` hold text-only overlays (questions, profiles, topics, councils, councilDetails, creeds) keyed by id; `dataFor(lang)` in `src/data/localized.ts` merges them over the English data. Ids, scores and structure come only from the English files.
- Generate an English skeleton for a new overlay with `scripts/i18n-skeleton.ts`.
- Inline `{ en, pl }` objects: `optionTerms.ts` (quiz tooltip "(soul sleep)" terms), `glossary.ts` (council-page tooltips, inflection-aware patterns `\p{L}*`), `councilMatters.ts`, `legal.ts`.
- URL slugs are always English: `councilSlug()` maps by council number, so localized names never leak into links.

## Language choice
- Flag dropdown next to the theme switch; links keep the current path and hash. Choice saved as `dc:lang`.
- `/` picks the language (see [[deploy]]); `<html lang>`, `og:locale`, hreflang per page.
